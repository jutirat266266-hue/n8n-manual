1. n8n คืออะไร? และสถาปัตยกรรมเบื้องหลัง

n8n (nodemation) คือระบบ Workflow Automation แบบ Node-based บนสถาปัตยกรรม Fair-code / Open-source ที่ขับเคลื่อนด้วย Node.js และ TypeScript ทำหน้าที่เป็นศูนย์กลางเชื่อมโยงแอปพลิเคชันหรือ API ต่างๆ เข้าด้วยกัน

คุณสมบัติเชิงเทคนิคที่สำคัญ:

  • Data Stream Format: ข้อมูลที่ไหลผ่าน n8n จะอยู่ในรูปแบบของ Array of Objects เสมอ โดยแต่ละ Object เรียกว่า Item และแต่ละ Item จะประกอบด้วยคีย์หลักคือ json (สำหรับข้อมูล Text/Number/Boolean) และ binary (สำหรับไฟล์ภาพ/PDF/Zip)
  • Self-Hosted Data Control: เมื่อติดตั้ง n8n บนเซิร์ฟเวอร์ส่วนตัว ข้อมูลทั้งหมดจะถูกประมวลผลอยู่ภายใน RAM/Database ของระบบคุณเองโดยไม่ผ่าน Cloud เซิร์ฟเวอร์ภายนอก
  • Execution Modes: รองรับการทำงานทั้งแบบ Single Process และ Scaling Mode ผ่าน Worker Container ร่วมกับ Redis และ PostgreSQL

💡 โครงสร้างข้อมูลพื้นฐานที่ n8n มองเห็น:
[ { "json": { "id": 1, "name": "Ta" } }, { "json": { "id": 2, "name": "CMG" } } ]

2. คำศัพท์ และส่วนประกอบเมนูการใช้งานจริง

การใช้งาน n8n ในหน้า Canvas หลัก ประกอบด้วยเมนูและคำศัพท์ที่ต้องเข้าใจดังนี้:

  • Canvas (ผืนผ้าใบ): พื้นที่ทำงานหลักใช้สำหรับวางและต่อสาย Node มีเครื่องมือ Zoom, Mini-map และ Grid Snap
  • Node Panel (กดปุ่ม +): แผงค้นหาและเลือกใช้ Node ซึ่งแบ่งหมวดหมู่เป็น Trigger, Action, Logic, AI และ Advanced
  • Input/Output Data View: หน้าต่างแสดงผลข้อมูลเมื่อดับเบิลคลิกที่ Node สามารถสลับดูได้ 3 รูปแบบ:
    • Table View: แสดงข้อมูลในรูปแบบตารางเหมือน Excel
    • JSON View: แสดงโครงสร้าง Code JSON ดั้งเดิม
    • Schema View: แสดงชื่อ Data Type (String, Number, Boolean, Array)
  • Credentials Manager: ระบบจัดการรหัสผ่าน API Key, OAuth2, Bearer Token โดยข้อมูลทั้งหมดจะถูกเข้ารหัสผ่าน N8N_ENCRYPTION_KEY ไว้ในฐานข้อมูล

3. การเริ่มต้นใช้งานและการตั้งค่า Workspace

ขั้นตอนปฏิบัติการเปิดใช้งานและสร้างไฟล์งานใหม่ใน n8n Dashboard:

  • เข้าสู่หน้า Dashboard โดยเปิด URL ของ n8n ผ่าน Web Browser (เช่น http://localhost:5678)
  • ที่แถบเนวิเกชันซ้ายมือ เลือกเมนู "Workflows"
  • กดปุ่มสีชมพู "Create Workflow" ตรงมุมบนขวา เพื่อเปิดหน้า Canvas ใหม่
  • คลิกที่ชื่อโปรเจกต์ตรงมุมซ้ายบน (ชื่อเริ่มต้น My Workflow 1) เพื่อตั้งชื่อระบบ เช่น CMG-Automation-Task
  • ไปที่เมนู Workflow Settings (ไอคอนรูปเฟืองด้านซ้าย) เพื่อตั้งค่าเพิ่ม เช่น การกำหนด Timezone (เช่น Asia/Bangkok) และการเปิด/ปิดการบันทึก Execution Data

4. สร้าง Workflow แรก (Step-by-Step)

ทดลองสร้าง Workflow เพื่อส่งและแปลงข้อมูลข้อความอย่างง่าย:

  • กดปุ่ม "+ Add first step" บน Canvas ➔ เลือก When clicking 'Test workflow' (Manual Trigger)
  • คลิกจุดวงกลม Output ฝั่งขวาของ Manual Trigger ลากสายเชื่อมต่อออกมา แล้วพิมพ์ค้นหา Edit Fields (Set)
  • ในหน้าต่างการตั้งค่า Edit Fields ให้กำหนดค่าดังนี้:
    • ในหัวข้อ Fields to Set กดปุ่ม "Add Field" ➔ เลือก String
    • ช่อง Name ใส่คำว่า: project_name
    • ช่อง Value ใส่คำว่า: n8n OCR System
  • กดปุ่ม "Execute Node" ด้านขวาบน ผลลัพธ์ในฝั่ง Output จะแสดงข้อมูล JSON:
{ "project_name": "n8n OCR System" }

5. เจาะลึกชนิดของ Trigger Node

Trigger คือจุดเริ่มต้นของกระบวนการ แบ่งออกเป็น 4 ประเภทหลักตามลักษณะการเรียกใช้จริง:

  • 1. Webhook Trigger: เปิด HTTP Endpoint รอรับ Request จากภายนอก (GET, POST, PUT, DELETE) รองรับการรับ Body ในรูปแบบ JSON, Form-Data และ Binary File
  • 2. Schedule Trigger: ตั้งเวลาทำงานตามรอบเวลา เช่น ทุก 1 ชั่วโมง, ทุกวันจันทร์เวลา 08:30 น. หรือใช้ Cron Expression แบบกำหนดเอง (เช่น 0 8 * * 1-5)
  • 3. App Events Trigger: คอยดักจับ Event จากบริการภายนอกผ่านการเชื่อมต่อ Webhook อัตโนมัติ เช่น Google Drive Trigger (เมื่อมีไฟล์ใหม่เพิ่มขึ้น) หรือ Gmail Trigger (เมื่อมีอีเมลใหม่เข้า)
  • 4. Form Trigger: สร้างเว็บฟอร์มหน้าต่างรับข้อมูลอย่างง่ายจาก n8n โดยตรงเพื่อนำข้อมูลเข้า Workflow ทันที

6. โครงสร้างประเภทของ Action และ Logic Nodes

รายละเอียด Node หลักที่ใช้ประมวลผลภายใน n8n:

  • Data Transformation Nodes:
    • Edit Fields (Set): สร้าง, แก้ไข, ตัด หรือเปลี่ยนชื่อคีย์ข้อมูล
    • Code Node: เขียนสคริปต์ JavaScript หรือ Python จัดการข้อมูลขั้นสูง เช่น การแปลงอาร์เรย์ การรวมคำสั่ง regex
    • Filter Node: กรองคัดเลือกเฉพาะ Item ที่ผ่านเงื่อนไขไปทำงานต่อ
  • Flow Logic Nodes:
    • If Node: แยกสายการทำงานเป็น True และ False ตามเงื่อนไขเปรียบเทียบ
    • Switch Node: แยกสายออกได้หลายทาง (Multiple Rules) เหมาะสำหรับการทำ Routing ตามประเภทข้อมูล
    • Loop Over Items: วนรอบประมวลผลข้อมูลชุดใหญ่ทีละกลุ่มหรือทีละ Item
  • External Integration Nodes: เช่น Google Sheets, Gmail, LINE Notify, Telegram, HTTP Request (สำหรับยิง REST API ทั่วไป)

7. การจัดการข้อมูลและการเขียน Expression (Data Mapping)

การอ้างอิงค่าจาก Node อื่นใน n8n ทำได้ 2 วิธีหลัก:

วิธีที่ 1: ลากและวาง (Drag & Drop)

ดับเบิลคลิกเปิด Node ปลายทาง ➔ มองในแถบ INPUT ฝั่งซ้าย ➔ คลิกค้างที่ชื่อตัวแปรที่ต้องการ แล้วลากมาวางในช่องตั้งค่าฝั่งขวา

วิธีที่ 2: การเขียนสูตร Expression (JavaScript-based)

สลับโหมดจาก Fixed เป็น Expression โดยคลิกไอคอน {{ }} หน้าช่องตั้งค่า แล้วพิมพ์สูตรอ้างอิง:

  • {{ $json.name }} : ดึงค่าจากคีย์ชื่อ name ของ Node ปัจจุบัน
  • {{ $('Node Name').item.json.email }} : ดึงค่าจาก Node ชื่อเฉพาะที่ระบุ
  • {{ $json.price * 1.07 }} : ทำการคำนวณตัวเลข (บวก VAT 7%)
  • {{ $json.title.toUpperCase() }} : ใช้คำสั่ง JavaScript String Method
  • {{ $now.format('yyyy-MM-dd') }} : ดึงวันที่ปัจจุบันในรูปแบบปี-เดือน-วัน

8. การทดสอบและการตรวจเช็กข้อผิดพลาด (Testing & Debugging)

ขั้นตอนการทดสอบอย่างถูกวิธีเพื่อความแม่นยำก่อนเปิดใช้งานจริง:

  • Test Single Step: กดปุ่ม "Execute Node" ภายใน Node นั้นๆ เพื่อรันเฉพาะบล็อกดังกล่าวโดยไม่กระทบ Node อื่น
  • Test Complete Workflow: กดปุ่ม "Test workflow" แถบด้านล่าง Canvas เพื่อรันตั้งแต่ Trigger จนจบสาย
  • การอ่านข้อผิดพลาด (Error Analysis):
    • หาก Node แสดง วงกลมสีแดง ให้กดคลิกเข้าไปที่ Node เพื่อเปิดแผง Error Details
    • อ่านค่า HTTP Code (เช่น 401 Unauthorized = รหัสผ่าน API ไม่ถูกต้อง, 404 Not Found = ไม่พบ URL/Endpoint)
    • ตรวจสอบ JSON Syntax Error กรณีเขียน Expression อ้างอิงตัวแปรที่ไม่มีอยู่จริง (Undefined)

9. การตั้งเวลาทำงานอัตโนมัติ (Schedule Trigger)

ขั้นตอนการสร้างและตั้งค่า Schedule Trigger สำหรับงานที่ต้องทำซ้ำตามเวลา:

  • วาง Node Schedule Trigger เป็น Node เริ่มต้นบน Canvas
  • ในหน้าตั้งค่า กำหนดเงื่อนไขเวลาในแผง Trigger Interval:
    • Every Hour: ให้รันทุกๆ กี่ชั่วโมง
    • Every Day: กำหนดเวลารันในช่อง Time Trigger Runs เช่น 08:00
    • Custom (Cron): ใส่รูปแบบ Cron เช่น 0 9 * * 1 (รันทุกวันจันทร์ เวลา 09:00 น.)
  • ทดสอบรันด้วยการกดปุ่ม Test workflow 1 ครั้งเพื่อดูว่าสายงานทั้งหมดทำงานถูกต้องหรือไม่

10. การจัดการข้อผิดพลาดด้วย Error Trigger (Error Handling)

การสร้างระบบแจ้งเตือนฉุกเฉินเมื่อเกิดความขัดข้องใน Production:

  • สร้าง Workflow ใหม่ขึ้นมา 1 ตัว ตั้งชื่อว่า Global-Error-Notifier
  • นำ Node Error Trigger มาวางเป็นจุดเริ่มต้น
  • ต่อสายจาก Error Trigger ไปยัง Node แจ้งเตือน เช่น LINE Notify หรือ Telegram หรือ Gmail
  • ในช่องข้อความแจ้งเตือน ให้พิมพ์สูตรดึงค่า Error Details:
🚨 แจ้งเตือนข้อผิดพลาดระบบ Automation! Workflow: {{ $json.workflow.name }} Workflow ID: {{ $json.workflow.id }} Node ล้มเหลว: {{ $json.execution.error.node.name }} ข้อความ Error: {{ $json.execution.error.message }} เวลาที่เกิดปัญหา: {{ $json.execution.lastNodeExecuted }}
  • เปิด Active Workflow Global-Error-Notifier นี้
  • ย้อนกลับไปที่ Workflow งานหลักของคุณ ➔ เปิดเมนู Workflow Settings (ไอคอนเฟือง) ➔ ในช่อง Error Workflow กดเลือก Global-Error-Notifier แล้วกด Save

11. การเชื่อมต่อ Webhook รับข้อมูล Real-time

การรับข้อมูลแบบ Instant Data Transfer จากภายนอกเข้ามายัง n8n:

  • วาง Node Webhook เป็นจุดเริ่มต้น
  • ตั้งค่า HTTP Method เป็น POST และ Path เป็นชื่อที่ต้องการ เช่น api/v1/receive-data
  • คัดลอก Test URL ไปใช้ทดสอบส่ง Request จากโปรแกรมต้นทาง (เช่น Postman, Python Script หรือ Google Forms Webhook)
  • กดปุ่ม "Listen for test event" ใน n8n แล้วกดสั่งส่งข้อมูลจากต้นทางเข้ามา
  • เมื่อ n8n แสดงข้อมูลที่รับได้บนหน้าจอ ให้สลับนำลิงก์ในช่อง Production URL ไปใส่ในระบบจริง

⚠️ ข้อควรระวัง: ลิงก์ Test URL จะทำงานเฉพาะตอนที่เราเปิดฟังในหน้าจอ Test เท่านั้น แต่ในการใช้งานจริงตลอด 24 ชั่วโมง ต้องใช้ Production URL และกดเปิด Active Workflow เท่านั้น

12. การเปิดใช้งานจริงและการจัดการประวัติ (Active & Executions)

ขั้นตอนสุดท้ายสำหรับการส่ง Workflow ขึ้นทำงานจริงใน Production:

  • ตรวจสอบสายงานและเปลี่ยน URL เชื่อมต่อภายนอกเป็นเวอร์ชัน Production
  • สังเกตสวิตช์มุมขวาบนของ Canvas สลับจาก Inactive เป็น "Active" (เปลี่ยนเป็นสีชมพู/เขียว)
  • กดปุ่ม Save (Ctrl+S / Cmd+S)
  • การตรวจสอบประวัติการรัน (Executions):
    • ไปที่เมนู "Executions" ที่แถบฝั่งซ้ายมือ
    • ระบบจะแสดงรายการการทำงานทั้งหมดย้อนหลัง สามารถคลิกเลือกดูรายการย่อยเพื่อตรวจสอบค่า Input/Output ของทุก Node ในรอบที่เกิดปัญหาได้อย่างแม่นยำ
Overview

เกี่ยวกับ n8n (Core Concepts)

แนวคิด สถาปัตยกรรมระบบ และข้อได้เปรียบทางเทคนิคของ n8n

1. สถาปัตยกรรมของ n8n

n8n ถูกพัฒนาบนภาษา TypeScript และ Node.js เพื่อประสิทธิภาพความเร็วสูงสุด การประมวลผลเน้นโครงสร้างแบบ Asynchronous Event-driven ช่วยให้รองรับการเชื่อมต่อ API หลายร้อยรายการพร้อมกันได้ดี

2. ข้อได้เปรียบเชิงเทคนิค

  • Self-Hosted Infrastructure: สามารถติดตั้งบน Docker, Kubernetes หรือ Virtual Private Server (VPS) ได้อิสระ ควบคุมความเป็นส่วนตัวของข้อมูลได้ 100%
  • No Execution Limits: สำหรับเวอร์ชัน Self-hosted จะไม่มีการจำกัดจำนวนการประมวลผล (Unlimited Workflow Executions)
  • Full Extensibility: รองรับการเขียน JavaScript/Python เพิ่มเติมภายใน Code Node รวมถึงการสร้าง Custom Node ขึ้นใช้งานเอง
Installation

วิธีติดตั้ง n8n บนเซิร์ฟเวอร์และคอมพิวเตอร์

คำสั่งติดตั้งอ้างอิงตามมาตรฐาน Official Documentation

1. การติดตั้งผ่าน Docker Container (แนะนำสำหรับการใช้งานจริง)

รันคำสั่ง Docker เพื่อสร้าง Container ของ n8n บนพอร์ต 5678 พร้อมผูก Volume สำหรับเก็บข้อมูลระบบ:

docker run -d \ --name n8n \ -p 5678:5678 \ -v n8n_data:/home/node/.n8n \ docker.n8n.io/n8nio/n8n

2. การติดตั้งผ่าน npx (สำหรับทดสอบด่วน)

สำหรับเครื่องที่มี Node.js (v18.x ขึ้นไป) และต้องการทดสอบใช้งานทันที:

npx n8n start
FAQ

คำถามที่พบบ่อย (FAQ)

ตอบข้อสงสัยยอดฮิตเกี่ยวกับการใช้งาน n8n

1. n8n สามารถประมวลผลไฟล์ภาพ หรือ PDF ได้ไหม?

ตอบ: ได้อย่างสมบูรณ์แบบ n8n มีระบบจัดการข้อมูลไฟล์ผ่านคีย์ binary สามารถรับไฟล์จาก Webhook, Google Drive หรือ HTTP Request เพื่อนำไปประมวลผลต่อ เช่น ส่งเข้า AI หรือทำระบบ OCR ได้

2. ถ้าฐานข้อมูล Execution เก็บเยอะเกินไป จะลบอัตโนมัติได้ไหม?

ตอบ: ได้ n8n มีระบบ Data Pruning โดยตั้งค่า Environment Variables เช่น EXECUTIONS_DATA_PRUNE=true และ EXECUTIONS_DATA_MAX_AGE=168 (เพื่อลบประวัติที่เก่าเกิน 7 วันอัตโนมัติ)
